    Before you run
    1. Table and column names spelled exactly (customers, name).
    2. One-row condition → WHERE. Group condition → HAVING.
    3. With GROUP BY, every other column sits inside COUNT/SUM/AVG/MIN/MAX.
    4. ORDER BY takes a column; LIMIT takes a number.
    5. Reread the question: columns, filter, order, how many.
    6. Subqueries go in parentheses. One value → = > <; a list → IN. Test the inner query on its own first.
    7. Dates are text like '2026-01-10'; strftime returns text, so compare to '2025' and '01' with quotes and leading zeros.
    8. CASE WHEN ... THEN ... ELSE ... END: the first true WHEN wins, and don't forget END.
    9. UPDATE and DELETE: always write the WHERE, and run a SELECT with the same WHERE first to see which rows it hits.
    10. JOINs: declare every alias after its table (FROM customers c) and match rows with ON o.customer_id = c.id.

    This sandbox runs SQLite, which is lenient in two places: it accepts aliases in HAVING, and it runs rule-3 mistakes by picking an arbitrary value instead of erroring. The answer checker still catches the wrong results, and it accepts your columns in any order.
